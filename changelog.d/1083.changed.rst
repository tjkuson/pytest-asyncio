All async fixtures and tests of an event loop now run in the same asyncio task and share one ``contextvars`` context. Tests with function-scoped loops still start from a fresh context, whereas tests sharing a module, class, package or session loop now see the context variables set by earlier tests and fixtures in that loop. Variables set in synchronous code are applied to the loop's context while an async fixture or test runs; variables an async fixture changes are applied to synchronous code until the fixture is torn down, as before.

A cancellation that reaches the task, for example because a task in a task group spanning a fixture's ``yield`` failed, ends the normal work of that loop: fixture teardowns still run, so that the scope can exit and report the failure, but further tests and fixture setups in the loop are refused with an ``asyncio.CancelledError`` explaining why. A cancelled fixture teardown is reported as ``PytestAsyncioError``. An interrupted test or fixture (Ctrl-C, or the signal of a timeout plugin) is cancelled and run to its end before pytest tears fixtures down.
