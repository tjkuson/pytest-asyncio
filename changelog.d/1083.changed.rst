All async fixtures and tests of an event loop now run in the same asyncio task. Each still runs in its own copy of the synchronous context, as before, so context variables behave as they did. Two things differ from a task of the fixture's or test's own: ``asyncio.current_task().get_context()`` is the context of the loop's task, and asyncio's call-graph tools do not show a suspended fixture or test.

A cancellation that reaches the task, for example because a task in a task group spanning a fixture's ``yield`` failed, ends the normal work of that loop: fixture teardowns still run, so that the scope can exit and report the failure, but further tests and fixture setups in the loop are refused with an ``asyncio.CancelledError`` explaining why. So does an interruption of a test or fixture (Ctrl-C, or the signal of a timeout plugin), which is cancelled and run to its end before pytest tears fixtures down. A cancelled fixture setup or teardown is reported as ``PytestAsyncioError``.
